## Phase 4 — Green Wave Preemption

### 4.1 Create `preemption/heap.py`
Initialize `heap.py` in the `preemption` module. This file implements the priority queue that ensures high-urgency vehicles are serviced immediately while preventing starvation of standard lanes. Import Python's built-in `heapq` module to manage the internal data structure.

### 4.2 Define `LanePriorityHeap` class
Create the `LanePriorityHeap` class within `heap.py`. Implement an `__init__` method that establishes an empty list to serve as the heap array. Also initialize a dictionary to track the current score of each `lane_id` to allow for O(1) lookups during score updates.

### 4.3 Implement `compute_score` method
Write `def compute_score(self, wait_time_s: float, density_veh_per_m: float, priority_multiplier: float) -> float:` inside `LanePriorityHeap`. The mathematical formula must combine these three factors into a single float, heavily weighting the `priority_multiplier`. Ensure that higher scores represent higher urgency.

### 4.4 Enforce anti-starvation invariant
Within `compute_score`, ensure the logic includes an additive term derived solely from `wait_time_s`. This guarantees that even if `density_veh_per_m` is 0, a lane that waits long enough will see its score increase monotonically. This prevents infinite starvation of low-density cross-streets.

### 4.5 Implement `push_or_update` method
Write `def push_or_update(self, lane_id: str, score: float):` to insert a new lane into the heap or update its score if it already exists. Because `heapq` does not support efficient updates, implement a tombstone mechanism: mark the old entry as invalid in a dictionary and push a new `(score, lane_id)` tuple. This maintains efficiency.

### 4.6 Implement `peek_root` method
Write `def peek_root(self) -> str:` to return the `lane_id` with the highest score without popping it. It must intelligently skip over any tombstoned entries left by `push_or_update`. This method guarantees O(1) retrieval time to quickly determine the next active lane.
